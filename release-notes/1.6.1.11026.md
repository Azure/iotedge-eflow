### Release Notes
- Azure Linux (formerly CBL-Mariner) [3.0.20261105 Release](https://github.com/microsoft/azurelinux/releases/tag/3.0.20261105-3.0)
- Azure IoT Edge [1.6.4](https://github.com/Azure/azure-iotedge/releases/tag/1.6.4)
- Enables migration from EFLOW 1.5 LTS to EFLOW 1.6 LTS.

**This release is available for X64 devices only. ARM64 devices remain on [EFLOW 1.5.7.01026](https://github.com/Azure/iotedge-eflow/releases/tag/1.5.7.01026).**

#### What's New
- EFLOW now runs Azure IoT Edge 1.6 LTS (`aziot-edge` 1.6.4 and `aziot-identity-service` 1.6.0) on Azure Linux 3.0.
- X64 devices running EFLOW 1.5.7.01026 can update to this release through Microsoft Update or Windows Server Update Services (WSUS).
- Fixed an issue where the in-VM (A/B) update failed with `no such table: hoststatus` on EFLOW VMs created from 1.5.7.01026. The update now repairs affected VMs; newly created VMs are not affected.
- Fixed an issue where the second of two consecutive updates, such as 1.5.6 to 1.5.7 to 1.6, could fail and roll back because the EFI system partition ran out of space. Update failures now also report the underlying error.
- Updated Azure Linux `ca-certificates` to 3.0.0-19 as part of the [eMudhra CA compromise mitigation](https://github.com/microsoft/azurelinux/issues/19714). This removes the affected root CA certificates from the EFLOW VM.
- After the update, EFLOW refreshes the CA trust store in the EFLOW VM and restarts the VM once if the trust store changed.
- Rebuilt the EFLOW Windows host components, `wssdagent` and `nodectl`, with Go 1.26.10.
- Rebuilt the guest compute service (GCS) in the EFLOW VM with Go 1.27.3.

#### Update Guidance
- Keep the Windows host patched, with automatic root certificate updates and disallowed certificate updates turned on.
- For update instructions, see [AzEFLOW-Update](https://aka.ms/AzEFLOW-Update).

#### Known Issues
- Running `sudo iotedge logs` can intermittently fail with `invalid character: '\x00' looking for beginning value`.
- [Restarting the EFLOW VM from inside the VM can stop it without starting it again.](https://github.com/Azure/iotedge-eflow/wiki/Support#issue-reboot-the-eflow-vm-from-inside-vm-will-stop-the-vm-but-wont-start-again) Use `Start-EflowVm` from PowerShell on the Windows host to start the VM again.
